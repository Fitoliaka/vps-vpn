# vps-vpn

Ниже — пошаговая инструкция, как купить VPS на **WeaselCloud (weasel.cloud)** с 4 IPv4-адресами (1 основной + 3 дополнительных) и настроить на нём личный VPN.

Я бы рекомендовал следующую схему:

- **VPS** — виртуальный сервер с Linux.
- **4 IPv4** — один основной адрес и три дополнительных, если провайдер позволяет назначить их серверу.
- **VPN** — WireGuard, современный, быстрый и относительно простой в настройке.
- **Твоя техника** — телефон, ноутбук или компьютер подключаются к VPN, а интернет-трафик идёт через сервер.

Важно: наличие четырёх IP не означает автоматически, что VPN будет использовать все четыре. Сначала нужно проверить, как именно WeaselCloud назначает дополнительные IP (secondary IP, failover IP, routed IP или отдельные адреса с MAC/виртуальным интерфейсом).

# **Часть 3. Настраиваем все четыре IP**

Это важный этап. У WeaselCloud дополнительные адреса могут отображаться в панели, но Ubuntu не всегда автоматически добавляет их к сетевому интерфейсу. Кроме того, DHCP после добавления IP может сменить основной адрес. Поэтому нужно аккуратно прописать все адреса в Netplan и не потерять первоначальный IP.&#x20;

## **Шаг 7. Сохраняем все IP из панели**

В личном кабинете открой свой VPS и найди раздел IP addresses.

Запиши все четыре адреса:

- IP №1 — первоначальный (основной);
- IP №2 — дополнительный;
- IP №3 — дополнительный;
- IP №4 — дополнительный.

Не используй адреса из примеров в моих командах. Пока не подставишь свои реальные IP, сетевую конфигурацию не применяй.

## **Шаг 8. Определяем сетевой интерфейс**

В SSH выполни:

```
ip -br a
```

Результат может выглядеть так:

```
lo       UNKNOWN   127.0.0.1/8
ens3     UP        198.51.100.10/24
```

Запиши имя интерфейса — в этом примере `ens3`. У тебя может быть `eth0`, `ens3` или другое имя.

Также проверь текущие файлы Netplan:

```
ls -l /etc/netplan/
```

И содержимое:

```
cat /etc/netplan/*.yaml
```

Не удаляй и не переписывай файл `50-cloud-init.yaml`, если он существует. Мы создадим отдельный файл, который будет содержать дополнительные адреса.

## **Шаг 9. Прописываем все IPv4 в Netplan**

Создаём отдельный файл:

```
nano /etc/netplan/60-extra-ips.yaml
```

Вставь шаблон, заменив адреса на свои реальные четыре IPv4, а имя интерфейса на найденное на шаге 8:

```
network:
  version: 2
  ethernets:
    ens3:
      addresses:
        - 111.111.111.111/32
        - 222.222.222.222/32
        - 333.333.333.333/32
        - 444.444.444.444/32
```

Здесь `ens3` — пример интерфейса, а IP — заглушки. Не оставляй их в итоговом файле.

Сохрани файл в nano:

- `Ctrl + O`
- Enter
- `Ctrl + X`

Устанавливаем безопасные права доступа:

```
chmod 600 /etc/netplan/60-extra-ips.yaml
```

Проверяем синтаксис:

```
netplan generate
```

Если ошибок нет, применяем с возможностью автоматического отката:

```
netplan try
```

Если SSH и сеть работают, подтверди конфигурацию. Если что-то пошло не так, не подтверждай — Netplan должен откатить изменения.

Не делай сетевые изменения без открытой SSH-сессии и доступа к Console в панели WeaselCloud.

## **Шаг 10. Проверяем, что четыре адреса появились**

```

# **Часть 4. Устанавливаем WireGuard — VPN-сервер**

Мы используем WireGuard. Он хорошо подходит для личного VPN, потому что:

- высокая скорость;
- небольшая нагрузка на VPS;
- простая настройка;
- приложения для Windows, macOS, Android, iPhone/iPad;
- можно настроить отдельный выходной IP для каждого устройства.

## **Шаг 11. Устанавливаем WireGuard**

На сервере:

```
apt install wireguard iptables qrencode curl -y
```

Включаем маршрутизацию IPv4:

```
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-wireguard.conf
```

Применяем:

```
sysctl --system
```

Проверяем:

```
sysctl net.ipv4.ip_forward
```

Должно получиться:

```
net.ipv4.ip_forward = 1
```

## **Шаг 12. Создаём ключи сервера**

Выполни:

```
mkdir -p /etc/wireguard
cd /etc/wireguard
```

Генерируем приватный и публичный ключи:

```
wg genkey | tee server_private.key | wg pubkey > server_public.key
```

Ограничиваем доступ к приватному ключу:

```
chmod 600 server_private.key
```

Посмотреть приватный ключ:

```
cat server_private.key
```

Посмотреть публичный:

```
cat server_public.key
```

Приватный ключ никому не отправляй, не публикуй и не вставляй в скриншоты. Публичный ключ можно передавать клиенту VPN.

## **Шаг 13. Узнаём внешний интерфейс**

Выполни:

```
ip route get 1.1.1.1
```

Пример ответа:

```
1.1.1.1 via 192.168.1.1 dev ens3 src 198.51.100.10
```

Запиши имя после `dev`. В данном примере это `ens3`.

Оно понадобится для настройки NAT.

## **Шаг 14. Создаём конфигурацию VPN-сервера**

Открываем файл:

```
nano /etc/wireguard/wg0.conf
```

Вставляем:

```
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = ВСТАВЬ_ПРИВАТНЫЙ_КЛЮЧ_СЕРВЕРА

PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -A FORWARD -o wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o ens3 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -D FORWARD -o wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -s 10.8.0.0/24 -o ens3 -j MASQUERADE
```

Замени:

- `ВСТАВЬ_ПРИВАТНЫЙ_КЛЮЧ_СЕРВЕРА` — на приватный ключ сервера из шага 12;
- `ens3` — на свой внешний интерфейс из шага 13.

Сохрани файл.

Затем:

```
chmod 600 /etc/wireguard/wg0.conf
```

Пока это базовая конфигурация, с которой весь VPN-трафик выходит через один IP. Чуть ниже я объясню, как распределить клиентов между четырьмя IP.

# **Часть 5. Открываем порт и запускаем VPN**

## **Шаг 15. Настраиваем Firewall**

Если SSH подключение уже работает, сначала разреши SSH, чтобы не заблокировать себе сервер:

```
ufw allow OpenSSH
```

Открываем UDP-порт WireGuard:

```
ufw allow 51820/udp
```

Включаем Firewall:

```
ufw enable
```

Проверяем:

```
ufw status
```

В списке должны быть SSH и `51820/udp`.

Если в панели WeaselCloud есть отдельный сетевой Firewall / Security Group, проверь, что там тоже разрешён входящий UDP 51820.

## **Шаг 16. Запускаем WireGuard**

Выполни:

```
systemctl enable wg-quick@wg0
```

Запускаем:

```
systemctl start wg-quick@wg0
```

Проверяем:

```
systemctl status wg-quick@wg0
```

Если видишь `active (exited)` или `active`, это нормально для wg-quick.

Дополнительная проверка:

```
wg show
```

# **Часть 6. Подключаем телефон или компьютер**

На примере первого клиента — телефона.

## **Шаг 17. Создаём ключи клиента**

На сервере выполни:

```
cd /etc/wireguard
wg genkey | tee client1_private.key | wg pubkey > client1_public.key
```

Права:

```
chmod 600 client1_private.key
```

Смотрим ключи:

```
cat client1_private.key
cat client1_public.key
```

Сохрани оба. Приватный ключ клиента предназначен только для самого клиента VPN.

## **Шаг 18. Добавляем клиента в WireGuard**

Открой серверную конфигурацию:

```
nano /etc/wireguard/wg0.conf
```

В конец добавь:

```
[Peer]
PublicKey = ПУБЛИЧНЫЙ_КЛЮЧ_CLIENT1
AllowedIPs = 10.8.0.2/32
```

Заменяй `ПУБЛИЧНЫЙ_КЛЮЧ_CLIENT1` на публичный ключ клиента из предыдущего шага.

Перезапускаем WireGuard:

```
systemctl restart wg-quick@wg0
```

Проверяем:

```
wg show
```

## **Шаг 19. Создаём файл подключения клиента**

На сервере узнай публичный ключ WireGuard:

```
cat /etc/wireguard/server_public.key
```

Теперь создаём конфигурацию клиента:

```
nano /root/client1.conf
```

Вставь:

```
[Interface]
PrivateKey = ПРИВАТНЫЙ_КЛЮЧ_CLIENT1
Address = 10.8.0.2/32
DNS = 1.1.1.1

[Peer]
PublicKey = ПУБЛИЧНЫЙ_КЛЮЧ_СЕРВЕРА
Endpoint = ТВОЙ_ОСНОВНОЙ_IP:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Замени три значения:

- `ПРИВАТНЫЙ_КЛЮЧ_CLIENT1` — приватный ключ клиента.
- `ПУБЛИЧНЫЙ_КЛЮЧ_СЕРВЕРА` — публичный ключ сервера.
- `ТВОЙ_ОСНОВНОЙ_IP` — IP VPS, доступный снаружи.

Сохрани файл.

# **Часть 7. Как сделать, чтобы VPN использовал все 4 IP**

Это самая важная часть именно твоей задумки.

**Четыре IP на VPS — это четыре адреса выхода в интернет.** Чтобы VPN-клиенты выходили через разные адреса, серверу нужно настроить правила, которые сопоставляют каждого клиента VPN с нужным IPv4.

Например:

| VPN-устройство | Внутренний IP WireGuard | Внешний IP |
| -------------- | ----------------------- | ---------- |
| Телефон 1      | 10.8.0.2                | IPv4 №1    |
| Телефон 2      | 10.8.0.3                | IPv4 №2    |
| Компьютер 1    | 10.8.0.4                | IPv4 №3    |
| Компьютер 2    | 10.8.0.5                | IPv4 №4    |

Таким образом, устройства подключаются к одному серверу, но внешние сайты видят разные IP.

## **Шаг 21. Добавляем правила привязки клиентов к IP**

Когда четыре адреса уже прописаны в системе, можно привязать конкретного клиента к определённому выходному IP.

Например, клиент с внутренним адресом `10.8.0.2` будет выходить через IPv4 №1, а клиент `10.8.0.3` — через IPv4 №2.

Для этого используются правила SNAT в таблице NAT. Они подменяют исходный адрес пакета на выбранный внешний IPv4.

Вариант настройки для четырёх клиентов:

```
iptables -t nat -I POSTROUTING 1 -s 10.8.0.2 -o ens3 -j SNAT --to-source IP_1
iptables -t nat -I POSTROUTING 1 -s 10.8.0.3 -o ens3 -j SNAT --to-source IP_2
iptables -t nat -I POSTROUTING 1 -s 10.8.0.4 -o ens3 -j SNAT --to-source IP_3
iptables -t nat -I POSTROUTING 1 -s 10.8.0.5 -o ens3 -j SNAT --to-source IP_4
```

Здесь нужно заменить:

- `ens3` — на твой интерфейс;
- `IP_1` — на основной IPv4;
- `IP_2` — на второй IPv4;
- `IP_3` — на третий IPv4;
- `IP_4` — на четвёртый IPv4.

Эти правила предназначены для выхода трафика каждого клиента через свой адрес. Их нужно сохранять после перезагрузки, а не просто выполнять вручную один раз.

Не вставляй эти правила в рабочую конфигурацию вслепую. В твоём wg0.conf уже есть общее MASQUERADE-правило. Нужно правильно поставить SNAT выше него и прописать удаление правил при остановке WireGuard, иначе можно получить конфликт или потерять настройки после перезапуска.

# **Часть 8. Проверяем, что VPN работает**

## **Шаг 22. Проверяем подключение**

Подключи телефон или компьютер к созданному VPN.

Открой браузер и зайди на:

- [https://2ip.ru](https://2ip.ru?utm_source=chatgpt.com)
- [https://ipinfo.io](https://ipinfo.io?utm_source=chatgpt.com)
- [https://browserleaks.com/ip](https://browserleaks.com/ip?utm_source=chatgpt.com)

Проверь:

1. IP должен быть IP твоего VPS, а не домашний.
2. Страна должна соответствовать локации сервера.
3. При подключении второго клиента, которому назначен другой IP, внешний IP должен отличаться.
4. Отключи VPN — внешний IP должен вернуться к твоему обычному.

Если у тебя работает только один IP, проверь на сервере:

```
wg show
```

И:

```
iptables -t nat -L POSTROUTING -n -v
